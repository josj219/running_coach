# 홈 대시보드 — 희망 목표 vs 현재 추세

> 2026-09-06 합의. "3달 뒤 목표가 있는데 게으르면 목표에서 멀어지는 게 보여야 한다"는 요구에서 출발.
> 첫 화면을 **홈(대시보드)** 으로 바꾸고, 옛 **기록** 탭은 홈 하단에 흡수했다. 탭: 홈 → 오늘 → 이번 주 → 설정.

## 원칙

1. **숫자는 앱이 결정적으로 계산한다.** AI는 해석만 한다. 주간 성장 리포트 카드 3숫자와 같은 원칙.
   같은 입력이면 매주 같은 숫자가 나와야 "추세"가 성립하고, 사용자가 숫자를 믿어야 동기부여가 된다.
2. **게으르면 멀어져야 한다.** 스피드만 보는 예측(Riegel)은 2주를 쉬어도 안 변한다.
   그래서 지구력(볼륨·롱런)이 부족할수록 거리 환산 지수를 올려 예상 기록을 늦춘다.
3. **근거를 그대로 보여준다.** 대시보드 "근거 보기"에 기준 기록·4주 평균·롱런·수행률·지수·공식을 노출한다.

## 산식 (`api/app/services/fitness.py`)

```
예상 기록  = min over 후보 c 의  t_c × (D_goal / d_c) ^ exp
후보       = 최근 8주 5km+ 기록 전부  ∪  프로필 PB(×1.05 페널티)
exp        = 1.06 + (1 − 지구력) × 0.25      (d_c < D_goal 일 때만 상향; 최대 1.31)
지구력     = 0.6 × min(1, 4주 평균 주간 km / 요구 km) + 0.4 × min(1, 4주 최장 롱런 / 요구 롱런)
```

| 상수 | 값 | 의미 |
|---|---|---|
| `RIEGEL_EXP` | 1.06 | 완전 준비 상태의 거리 환산 지수 |
| `ENDURANCE_EXP_SPAN` | 0.25 | 지구력 0일 때 지수 가산 |
| `SPEED_WINDOW_DAYS` | 56 | 스피드 기준점 탐색 창 |
| `MIN_REF_KM` | 5 | 기준점 최소 거리 (3km 전력 질주로 풀 외삽 금지) |
| `PB_PENALTY` | 1.05 | 프로필 PB(날짜 미상) 페널티 |
| `CANON_KM` | 10 | PB는 10K 환산 스피드 증거로만 사용 |
| `VOLUME_WINDOW_DAYS` | 28 | 지구력 산출 창 |
| `REQUIREMENTS` | 풀 60/30 · 하프 45/18 · 10K 35/12 · 5K 30/10 | 목표 거리별 (주간 km, 롱런 km) 요구치 |

### 왜 PB를 항상 후보에 두나
최근 8주가 이지 런뿐이면 "8km 5:40/km"가 유일한 스피드 증거가 되어 예상 기록이 5시간대로 튄다.
스피드는 빨리 사라지지 않으므로 PB(페널티)를 **스피드 하한**으로 두되, PB의 당시 지구력은 끌어오지 않도록
10K로 환산한 뒤 **현재** 지구력 지수로 다시 외삽한다. 지수는 볼륨을 따라 움직이므로 게으르면 멀어지는 성질은 유지된다.

### 보정 근거 (고고조 데이터)
| 기준 | 순수 Riegel 풀 환산 | 실제 풀 |
|---|---|---|
| 10K 42:13 | 3:14 | 3:51 (주 30km, 마지막 2km 걸음) |
| 하프 1:38 | 3:24 | 3:51 |

당시 주 30km·롱런 ~20km → 지구력 ≈ 0.57 → 지수 1.17 → 10K 기준 예상 3:46. 실제 3:51과 근접.

### 준비도 3축 (0~100)
- **스피드**: 기준 기록의 순수 환산(지수 1.06)이 목표 대비 얼마나 빠른가. 목표 이하 100, 5% 느리면 80, 25% 느리면 0.
- **지구력**: 위 지구력 × 100.
- **꾸준함**: 최근 4주 계획 수행률(휴식 제외, done/partial = 완료). 표시 전용 — 예상 기록에는 볼륨으로 이미 반영.

### 요구 궤적
목표를 설정한 시점(`goals.created_at`)의 예상 기록에서 목표일의 목표 기록까지 **직선**.
매주 예상 기록이 이 선 위에 있는지 아래인지가 "궤적 대비 ±N 뒤처짐/앞섬". 앵커가 고정이라 매주 비교가 가능하다.

## API

`GET /api/dashboard` (`api/app/routers/dashboard.py` → `services/progress.py`)

```
goal     : {race_type, distance_km, target_time, target_sec, target_date, dday, weeks_left} | null
current  : {as_of, predicted_sec, predicted_time, gap_sec, delta_week_sec, required_sec, vs_required_sec,
            readiness:{speed, endurance, consistency}, basis:{reference, exponent, vol_4wk_km, long_run_km, …}}
anchor   : {date, predicted_sec} | null
series   : 최근 12주 [{week_start, iso_week, as_of, predicted_sec, required_sec, week_km, current}]
message  : 안내 문구 | null   (목표 없음 / 기준 기록 없음 / PB 로 추정 중)
```

스냅샷 테이블은 없다. 로그로부터 매번 재계산하므로(주당 1회 `snapshot`, 12주 + 앵커) 기존 Strava 기록만 있으면
배포 첫날부터 12주 궤적이 그려진다. 지난 주는 일요일 기준, 이번 주는 오늘 기준(진행 중).

## AI 연동

`render_fitness_context` 가 같은 숫자를 `## 목표 진척도(앱 산출 — 재계산 금지, 해석만)` 섹션으로 만들어
**주간 계획 생성**과 **주간 성장 리포트** 프롬프트에 넣는다. 리포트의 "목표 진척도" 표는 이 숫자를 인용만 하고,
격차가 남은 기간으로 못 메우는 수준이면 코치 메시지에서 수정 목표를 제안하도록 프롬프트에 명시했다.

## UI (`web/src/tabs/Home.jsx`)

위에서부터: 목표 격차 카드(희망 목표 | 현재 추세, 격차 배지, 지난주 대비, 궤적 대비) → 예상 기록 궤적(SVG, 위로 갈수록 빠름,
현재 추세 실선 · 요구 궤적 점선 · 목표 점선) → 준비도 3바 + 근거 보기 → 오늘 한 줄(탭하면 오늘 탭) → 주간 거리 8주 → 최근 훈련.
오늘 탭 상단에도 "목표 3:30 · 현재 추세 4:31 +1시간 1분" 한 줄을 반복 노출한다(탭하면 홈).
