# 사용자 여정 반영 계약 (2026-09-13)

## 판단과 데이터

- 현재 값은 기록 기준 거리 환산이다. Riegel 기반 산식과 지구력 계수는 휴리스틱이며 대회 결과에 의한 오차·보정 검증은 아직 없다. 고정 운동량 기준은 산식 입력이며 개인 훈련 처방이 아니다.
- 데이터 충분성: 최근 28일 적합한 러닝 6건, 관측 기간 14일, 마지막 기록 14일 이내. 근거가 부족하면 준비도 점수를 숨긴다. PB만 있으면 참고 환산과 달성일 미상을 표시한다.
- 러닝 종목이 확인된 기록만 러닝 거리에 집계한다. 추정에는 양의 거리·시간, 2~20분/km, 직접 입력 페이스와 계산 페이스 차이가 15초 또는 10% 이내인 기록을 사용한다. 범위 밖 기록도 원본은 보존한다. 기존 `other`는 미확인으로 남기며 사용자가 러닝으로 확인할 수 있다.
- 가용 시간·남은 계획·체크포인트는 조건부 검토에 사용한다. 검증되지 않은 미래 기록·달성 확률·예측 범위를 만들지 않는다. 운동량 감소를 게으름이나 실력 저하로 단정하지 않는다.

## 기록과 수행

- POST `/api/workout-logs`는 독립 운동 추가, PATCH `/{id}`는 해당 운동 수정이다. `client_request_id`는 동일 저장 시도의 재시도 키다. PATCH는 변경 필드와 `log_date`를 받으며 `expected_revision`으로 충돌을 감지할 수 있다.
- 외부 공급자 ID는 같은 정규 기록에 연결한다. 다른 공급자는 시작 시각 60초 이내, 거리 차이 0.1km 또는 2% 이내, 시간 차이 10초 또는 2% 이내를 모두 만족할 때만 같은 운동으로 연결한다. 날짜만 같다는 이유로 병합하지 않는다. 메타데이터가 다른 중복은 사용자가 확인하고 하나만 선택해야 한다.
- 기록 여부와 참여율/계획 이행률은 별개다. 이행은 계획 거리(없으면 시간)의 90% 이상, 수치 없는 계획은 사용자 확인을 사용한다. 명시적 부분 수행은 부분으로 남긴다. 부분/대체는 참여에만 포함한다.
- 계획 연결은 선택적이다. 계획 생성 전의 미연결 운동을 후속 계획에 강제로 연결하지 않는다. 승인된 계획 변경은 원래 계획과 변경 사유를 사건으로 보존한다.
- 당일 기존 카드 변경은 제안을 저장하고 사용자가 변경 전후를 확인한 뒤 적용한다. 제안은 30분 유효하며 계획·기록이 바뀌면 재생성이 필요하다. 완료 기록은 보존한다.

## 당시 평가와 성장

- `assessments`는 평가일·목표 ID·계산 버전·입력 hash·입력·당시 결과를 append-only로 저장한다. 목표 수정은 새 Goal ID다. 프로필/PB 변경·기록 정정 전후 평가를 보존한다.
- 홈 성장선은 실제 저장한 평가만 연결한다. 현재 입력으로 과거를 다시 계산한 값은 소급 추정으로 별도 표시한다. 스냅샷 도입 전에 이미 덮어쓴 역사까지 복구할 수는 없다.
- 코칭 과제는 선택 당시 근거, 반영 훈련 또는 보류 사유, 다음 평가의 실제 수행을 유지한다. 근거가 정정된 옛 AI 해석은 보류한다.
- 성장 기록실은 7일/28일/목표 기간과 직전 같은 길이 기간의 실제 거리·시간을 비교한다. 같은 사용자 비교 조건·훈련 종류·0.1km 거리 구간에 양쪽 각 2건 이상일 때 페이스를 보조 비교한다. 심박은 체감도 같은 표본만 표시한다. 미관측 환경 차이를 제거한 인과적 실력 지표는 아니다.
- Expo도 인증·복수 기록·ID 수정·재시도 ID·외부 활동 ID 계약을 사용한다. Native 실기기 검증과 미래 기록 모델 보정은 별도다.
